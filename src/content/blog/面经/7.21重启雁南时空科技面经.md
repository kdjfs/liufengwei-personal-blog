## websocket、http长轮询、SSE有什么区别

基础本质：

长轮询基于普通HTTP，客户端发送请求，服务端不立即返回，有数据/超时才响应；循环实现伪长连接

SSE：单向长连接，浏览器主动建立，只能服务端推，客户端不能发，复用HTTP协议

WebSocket：独立协议，握手用HTTP，握手完成后  **双向全双工通信**，客户端服务端可随时发送消息

 1、通信方向上

长轮询是一问一答，单向的

SSE仅后端推送，前端不能发

WebSocket ：双向全双工

2、协议

长轮询：纯HTTP，每次新建请求

SSE：HTTP，text/event-stream长连接

WebSocket：HTTP握手 -》切换ws独立协议

3、开销

长轮询：开销最大，重复请求头

SSE：中等

WebSocket：最小，轻量帧传输

4、数据格式

长轮询：文本/JSON格式

SSE：仅文本，不支持二进制

WebSocket：文本+二进制

5、重连机制

长轮询：天然自动重连

SSE：浏览器原生自动重连

WebSocket：无原生，需手动心跳重连

一句话背：**单向推送选SSE，双向交互用WebSocket，老旧兼容用长轮询兜底**





## JWT组成结构、优缺点；与Sessiong的区别

**JWT由头部、载荷、签名组成**

头部：加密算法，base64编码，令牌类型

载荷：存放用户信息，过期时间等自定义信息，base64编码（未加密，不能存放敏感信息）

签名：头部+载荷+密钥加密，防止篡改

优点：

无状态：服务器不用存会话，分布式友好

前后端分离适配，跨域方便

自带用户信息，减少数据库查询

适合小程序、移动端、多端项目

缺点：

令牌无法主动失效，注销、下线难处理

载荷仅base64编码，明文可解码，不能存密码、手机号

一旦签发，未过期前无法修改权限

体积大，每次请求携带，增加传输开销



与Session对比

**JWT头部、载荷、签名，无状态适合分布式，Session存服务端可控失效，JWT存客户端无法主动销毁**

JWT存在客户端的token里，session存放在服务端，客户端只存session cookie

session有状态，JWT无状态

session服务端可直接删除，随时下线用户;JWT 到期前无法作废，需Redis黑名单兜底

seeion敏感数据放服务端更安全；JWT载荷可解码，禁止存放敏感数据

session依赖cookie，移动端、跨域麻烦；；JWT放header请求，适配小程序、APP、前端



## typescript泛型是什么和用法和项目高频使用场景，TS联合类型和交叉类型有什么区别

## WebSocket断线重连，如何防止无线重连

## ⭐⭐⭐⭐⭐ vue响应式和react响应式区别

1、底层原理

vue依靠proxy数据劫持，读取数据自动收集依赖，修改数据精准触发更新，全自动响应

react 无数据劫持，没有依赖收集；只有调用usestate/setState才强制触发组件重渲染

2、更新机制

vue 颗粒度更新，精准更新到该变量的视图，局部刷新不整组件重跑

react 组件级更新，状态一变整个函数重新执行，默认全量重渲染

3、数据修改方式

vue支持直接修改源数据

obj.name = "" , arr,push() 自动响应

react 遵循不可变数据，必须返回 **全新引用**，不能改原数据

4、依赖管理

vue自动收集依赖 ， computed，watch effect 不用手动写依赖数组

reactt的

useMemo,useCallback,useEffect，必须手动维护依赖数组，极易出错



5、性能优化方向

vue 天生新能好，日常不用手动优化

react 必须手动优化

memo缓存组件，usememo 缓存值，useCallback 缓存函数，否则大量无效渲染



## ⭐ vite webpack 优缺点 区别  （最经典的答案，别跳）

Vite vs Webpack 核心区别（面试版）

一、核心区别（一句话）

- Webpack：打包优先，开发/生产都要全量打包，基于自己的模块系统。
- Vite：开发不打包、按需编译；开发用浏览器原生ESM+esbuild，生产用Rollup打包 。

1）启动方式

- Webpack：先遍历全项目依赖、打包成bundle，再启动服务 → 项目越大越慢 。
- Vite：只启动一个轻量http服务器，不打包业务代码 → 毫秒级启动。

2）转译工具

- Webpack：用 Babel（JS单线程） 做TS/JSX转译，慢 。
- Vite：用 esbuild（Go语言多线程），比Babel快 10–100倍 。

3）热更新 HMR

- Webpack：改文件 → 重新打包该模块+依赖 → 浏览器整体更新。
- Vite：改文件 → 仅失效当前模块 → WebSocket通知浏览器直接拉新模块，毫秒级。

4）模块处理

- Webpack：全量构建依赖图，不管用不用都打包 。
- Vite：依赖预构建（esbuild）+ 源码按需请求，用哪个编译哪个 。

5）配置与生态

- Webpack：配置复杂、loader/plugin生态极强、兼容IE。
- Vite：开箱即用、配置极简、生态较弱、不支持IE。

 

二、优缺点对比（面试直接说）

Webpack 优点

1. 生态最成熟：loader/plugin应有尽有，老项目迁移友好。
2. 兼容性最强：支持 CJS/AMD/ESM，可兼容IE11。
3. 生产优化强：代码分割、tree-shaking、持久化缓存非常成熟。

Webpack 缺点

1. 启动慢、热更慢：项目越大越明显。
2. 配置繁琐：loader/plugin 一大堆，上手成本高。

Vite 优点

1. 开发极速：冷启动毫秒级、HMR 100ms内。
2. 配置极简：内置TS/JSX/CSS支持，几乎零配置。
3. esbuild+Rollup双引擎：开发快、生产打包体积小 。

Vite 缺点

1. 生态较弱：部分Webpack插件没有Vite版。
2. 不支持IE：依赖浏览器原生ESM。
3. 超复杂构建场景（多页、超大分包）不如Webpack成熟。

 

三、Vite 为什么比 Webpack 启动快（必背三点）

1）开发环境不打包，用浏览器原生 ESM

- Webpack：启动前必须打包全项目，构建完整依赖图 。
- Vite：启动只开服务器，业务代码不打包，浏览器  import  哪个，Vite实时编译哪个。

2）依赖预构建 + esbuild（Go语言）极速转译

- 第三方依赖（vue/axios）用 esbuild一次性预构建成ESM，缓存到  .vite ，只做一次 。
- esbuild是Go多线程，比Babel（JS单线程）快几十倍 。

3）HMR 机制完全不同，无全局重构建

- Webpack：改文件 → 重新打包依赖链 → 慢。
- Vite：改文件 → 只更新当前模块 → WebSocket通知浏览器直接请求新模块，毫秒级。

 

四、一句话终极总结（面试结尾）

Webpack是全量打包、配置强、生态稳、启动慢；Vite是ESM按需、esbuild极速、零配置、开发体验碾压Webpack，生产用Rollup，适合现代项目。

 





## 项目首屏加载性能优化全套方案

首屏加载性能优化（面试完整版，直接背诵）

一、网络优化

1. 开启 Gzip/Brotli 压缩静态资源，减小传输体积
2. 静态资源部署 CDN，就近访问减少延迟
3. 启用 HTTP2/HTTP3，实现请求多路复用
4. 合理利用浏览器缓存：强缓存+协商缓存，静态资源加哈希文件名
5. DNS预解析、预连接，提前建立请求链路
6. 首屏接口精简字段、合并请求、分页加载，避免海量数据阻塞

二、资源加载优化

1. 路由懒加载，拆分打包JS，只加载首页路由代码
2. 图片优化：压缩图片、使用WebP格式、大图懒加载、合理使用雪碧图
3. 字体优化：字体精简、 font-display:swap  避免字体闪烁
4. 非首屏组件、弹窗、图表延迟动态导入加载
5. 使用  preload  预加载首屏关键资源， prefetch  预加载后续页面资源

三、打包构建优化

1. 开启Tree-Shaking，剔除无用死代码
2. 第三方依赖分包拆分，分离公共库，利用长效缓存
3. UI组件库按需引入，杜绝全量引入增大体积
4. 剔除生产环境日志、调试代码、冗余注释
5. Vite/Webpack开启构建缓存，提升二次打包速度

四、JS执行优化

1. 拆分长耗时同步任务，利用空闲时间执行
2. 减少首屏超大JS文件加载，非核心逻辑延后执行
3. 避免全局过多初始化逻辑阻塞页面渲染
4. 合理使用 async/defer ，防止JS阻塞HTML解析

五、浏览器渲染优化

1. CSS放头部，JS放底部，优先渲染页面样式
2. 精简首屏DOM节点数量，减少渲染树构建开销
3. 减少页面频繁重排重绘，动画优先使用 transform/opacity 
4. 避免首屏大量内嵌大体积样式

六、用户体验优化

1. 加入骨架屏、加载动画，优化白屏等待感知
2. 页面白屏阶段优先展示基础布局

七、高阶渲染优化

1. SSR服务端渲染：服务端直出HTML，大幅提升首屏速度与SEO
2. SSG静态生成：提前打包静态页面，访问无渲染耗时
3. 移动端开启视口适配，优化移动端加载体验

八、排查手段

1. 使用Lighthouse做性能打分，定位短板
2. Chrome Performance分析长任务
3. Network查看资源加载耗时与请求瀑布流

极简背诵口诀

压缩缓存CDN，路由图片做懒加载
分包按需删冗余，拆分长任务
优化渲染减DOM，骨架屏提体验
高阶用上SSR，首屏速度直接拉满





## webpack中的Loader和Plugin的区别

## 一、核心区别速记版（好背）

### 1. 作用定位

- **Loader**：文件**转换器**，只处理单个文件，把非 JS / 非 JSON 资源（css、图片、vue 等）转成 Webpack 能识别的模块
- **Plugin**：流程**扩展器**，监听 Webpack 生命周期钩子，干预整个打包全过程（打包优化、资源输出、环境注入等）

### 2. 运行时机

- Loader：在**模块解析阶段**执行，按从右到左顺序链式调用
- Plugin：在**整个编译生命周期**的各个钩子节点触发（初始化、编译、输出结束等）

### 3. 配置写法

- Loader：写在`module.rules`里，匹配`test`文件后缀使用
- Plugin：直接实例化放进`plugins`数组

### 4. 典型例子

Loader：`css-loader`、`style-loader`、`file-loader`、`babel-loader`

Plugin：`HtmlWebpackPlugin`、`CleanWebpackPlugin`、`DefinePlugin`

## 二、一句话背诵口诀

Loader**翻译单个文件**，Plugin**操控打包全流程**。
