# 二、各问题精简核心答案

## （一）岗位 & 业务认知

### 1 岗位理解

岗位三件事：1）基于现有框架快速完成客户定制化页面、交互修改交付；2）配合产品从前端视角完善功能设计；3）异地协同四川研发团队完成内部系统开发，只做前端，不用写后端。

## （二）自我介绍

大三 27 届应用数学本科，大二自学前端；掌握 HTML/CSS/ES6/Vue3/uni-app，熟悉 Element Plus、uView，懂 Vite/Webpack、Git；

项目：电影选座 Demo、鉴酒三端 RBAC 小程序、智慧生猪开源系统（95star）；

掌握请求封装、骨架屏、图片懒加载、分包等性能优化，可长期实习 4-6 个月。

## （三）需求对接 & 协作流程

### 1 需求来源 & 对齐

无专职产品 / UI，后端提供设计图 + 接口文档；拿到 UI 稿和接口文档，按页面拆分开发；接口字段缺失、逻辑不合理直接和后端沟通调整。

### 2 UI 对接

无专职 UI，参照固定效果图开发；接口异常、字段缺失主动和后端协商修改。

## （四）代码规范、自测、版本管理

### 1 提交前检查

清除控制台报错、警告；完整自测全部交互；确认新增功能闭环；再提交代码。

### 2 功能完成判定标准

1. 页面 UI 和效果图一致；
2. 所有交互按钮正常，重复操作无 bug；
3. 调用接口后端数据库产生对应数据；
4. 弹窗、状态提示正常展示。

### 3 版本管理

单人开发，极少新建分支；采用 Git 规范提交备注，按单个小功能分次提交，不一次性批量提交；无多人冲突场景。

## （五）业务场景思考题

### 1 还车功能异常场景

1. 弱网 / 断网：操作按钮加 loading，禁止重复点击防重复请求；
2. GPS 定位失败：弹窗提示开启高精度定位，移动空旷区域重试；
3. 不在指定还车区域：拦截提交，提示前往合规点位；
4. 重复点击还车：按钮置灰节流，防止重复发请求。

### 2 线上 bug 排查思路

1. 区分环境：核对生产环境 BaseURL 是否配置错误；
2. 缓存问题：引导用户清理浏览器 / 小程序缓存、强制刷新；
3. 设备兼容：老旧手机、低版本系统、浏览器适配问题；
4. 复现报错：查看控制台接口报错、JS 异常；
5. 后端排查：核对生产接口返回数据是否异常。

## （六）个人基础信息匹配

### 1 作息地点

可以接受肇庆办公，单休 9-18 点，在校无课程，可当地租房长期实习。

### 2 长期规划

公司技术体系完善、有晋升空间、能持续成长，毕业后愿意长期稳定任职，争取转正。

### 3 设备

### 4 薪资

清楚薪资结构，无疑问，等待人事确认实习薪资细则。

### 5 协作分工

仅负责前端，对接本地产品，异地协同四川后端团队，不用写后端代码。
