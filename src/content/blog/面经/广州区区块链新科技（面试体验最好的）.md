# 二、各问题精简核心答案

## 1. 项目基础 & 登录权限

### 1.1 项目介绍

1. 前端三件套 + Vue3，独立负责 2 个全栈合作项目，uni-app 开发三端（小程序 / H5 / 后台）
2. 智慧生猪：疾病管理、AI 问诊，GitHub 90+star；鉴酒小程序三角色 RBAC 权限系统
3. 掌握 vite、webpack 打包基础

### 1.2 未登录路由拦截

全局路由守卫校验 localStorage 角色 token，无登录凭证强制跳转登录页；支持配置部分免登页面。

### 1.3 鉴酒下单 & 订单流程

1. 下单必传 6 张酒品照片、3 张选传，填写渠道、鉴定时间；
2. 用户付费下单，鉴定师抢单，一对一图文聊天；
3. 鉴定完成且用户允许公开，鉴定记录展示在社区帖子。

### 1.4 鉴定师激励与付费

1. 接单赚取服务费；指定订单仅目标鉴定师可接，公开订单全体鉴定师可抢；
2. 订单分待付款、鉴定中、已鉴、已退款等状态；
3. 前端仅展示付款二维码模拟支付，支付逻辑由后端完成。

### 1.5 退款状态流转

1. 用户提交退款表单（订单 ID、退款理由）调用退款接口；
2. 订单变为「退款审核中」；后端审核通过状态改为「已退款」，前端订单分类展示。

## 2. 实时通信轮询

### 2.1 短轮询实现增量拉取消息

每 5s 定时请求，携带**最后一条消息 ID**，后端仅返回大于该 ID 的新增消息，减少传输量。

### 2.2 轮询请求时序错乱解决方案

1. 增加请求锁：同一时间只允许 1 个请求进行，上一次未响应则取消 / 跳过本次轮询；
2. 每条消息携带全局唯一时间戳，前端按时间戳重排序渲染；
3. 采用防抖 / 节流控制请求频率。

### 2.3 短轮询 vs 长轮询

1. 短轮询：客户端定时主动发请求，无数据也直接返回，资源消耗大、延迟固定；
2. 长轮询：请求挂起，服务端有新数据再响应，无数据保持连接，实时性更好，减少无效请求。

### 2.4 轮询 vs WebSocket

1. 轮询基于 HTTP 短连接，定时重复请求，延迟高、请求多，实现简单、服务器成本低；
2. WebSocket 基于 TCP 长连接，双向实时推送，毫秒级通信，并发高时服务器压力大；
3. 项目聊天交互低频，选择短轮询降低服务端成本。

## 3. CSS 布局

### 3.1 Flex 三列等高、动态内容完整展示（纯 CSS）

父容器 `display: flex; align-items: stretch;`

- stretch 默认让所有子元素高度等于最高子项；
- 子元素内部使用 `overflow: visible` 完整展示文字，不截断、不出现滚动条。

### 3.2 CSS 布局核心要点

熟悉属性继承；开发前基于 UI 稿预设多端响应式布局方案，提前规避平板、大屏适配问题，UniAPP 仅能简化移动端，Web 端需独立适配宽度。

## 4. JS 基础

### 4.1 数组去重（禁用 Set/Map）

双重 for 循环遍历，内层对比元素，重复项 splice 删除；或创建空数组，遍历原数组用 indexOf 判断是否已存在，不存在再 push。

### 4.2 闭包核心

1. 定义：函数嵌套，内部函数引用外部函数变量，作用域链保留变量；
2. 优点：保存私有变量、模块化、数据持久；
3. 缺点：变量无法被 GC 回收，易造成内存泄漏，长时间页面驻留占用内存。

## 5. 组件封装 & 首屏优化

### 5.1 UI 组件二次封装

1. 封装场景：页面多处复用模块（订单卡片、通用表单、操作按钮）；
2. 封装思路：基于组件库基础组件，统一业务样式、默认参数、事件；通过 props 传参控制展示内容；
3. 示例：封装订单卡片组件，传入订单数据自动渲染图片、鉴定师、商品信息，多页面复用。

### 5.2 首屏优化落地

1. 骨架屏：接口未返回数据时展示灰色占位布局，消除白屏；
2. 图片懒加载：uni-app image 开启 lazy-load，仅加载可视区域图片，节省流量；
3. 分包、减少首屏请求资源。
