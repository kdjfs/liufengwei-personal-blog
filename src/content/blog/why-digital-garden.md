社交平台适合让一段想法快速流动，但不擅长让它在几年后仍然容易找到。数字花园更像自己的工作台：内容可以不完整，可以被修订，也可以随着新的理解长出连接。

## 写作是整理，不是展示

当我试图把一个概念解释给另一个人时，模糊的地方会立刻暴露。写作不是给已经完成的思考做包装，而是思考本身的一部分。

> “如果一句话无法被写清楚，通常不是表达的问题，而是理解还没有完成。”

这也意味着文章不必追求“永远正确”。它只需要清楚标注时间、上下文与更新记录，让后来的自己知道当时为什么这样判断。

## 从收藏信息到建立连接

传统文件夹强迫一条笔记只属于一个位置，标签则允许它同时进入多条脉络。LFW Space 同时保留分类与标签：

- **分类**描述文章主要属于哪个稳定主题；
- **标签**描述它还和哪些具体技术或问题相关；
- **相关文章**根据共享分类和标签建立弱连接；
- **搜索**负责处理无法预先归类的探索。

> [!IMPORTANT]
> 数字花园的价值不取决于条目数量，而取决于内容是否能被重新找到、重新理解和重新使用。

## 让维护成本足够低

如果发布一篇文章需要登录后台、配置数据库、处理服务器和维护复杂编辑器，写作很容易被工具本身阻塞。当前阶段只保留一条短路径：

```bash
pnpm new:post
pnpm dev
```

脚本生成通过 Schema 校验的 frontmatter，文章仍然是普通 Markdown 文件。它可以被 Git 追踪，可以迁移，也不会被某个私有平台锁住。

## 花园会如何生长

未来这里会逐步加入评论、浏览量与更好的内容推荐，但这些能力不能反过来污染文章系统。无论后端如何演进，Markdown 内容和静态构建都应该继续作为可靠的基础层。
