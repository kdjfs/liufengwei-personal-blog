这是你的第一块地基。

# 第 4 章：RAG 到底是什么

这一章必须达到“面试标准答案”。

RAG：

> Retrieval-Augmented Generation
> 检索增强生成。

核心问题：

LLM 有三个天然缺陷：

```text
知识可能过时
不知道你的私有数据
可能产生幻觉
```

所以：

```text
用户问题

   ↓

Retrieve
检索相关资料

   ↓

Augment
把资料塞入上下文

   ↓

Generate
LLM 根据资料回答
```

记住：

> RAG 不等于向量数据库。

这是一个非常重要的面试点。

RAG 的 Retrieval 可以是：

```text
关键词检索
BM25
全文检索
向量检索
Hybrid Search
数据库查询
知识图谱
API
```

你的博客就是一个非常好的例子：

**没有向量数据库，一样可以属于 Retrieval-Augmented Generation 思路。**

README 也明确说明当前 AI Retrieval 2.0 使用：

- Metadata 查询
- Heading Chunk
- 中英混合词法检索
- 不使用 Vector DB。

这一章会是你的重中之重。

# 第 5 章：Chunk —— RAG 最容易被面试官追问的地方

你特意提到了 Chunk，这个必须重点学。

Chunk 就是：

> 把一个大文档拆成若干适合检索的小文本块。

比如：

```text
Vue3 源码文章
10000 字
```

如果整个文章作为一个 Document：

```text
Query：
“最长递增子序列有什么作用？”
```

检索粒度太粗。

于是：

```text
Vue3源码.md

├─ Chunk 1
│  Virtual DOM
│
├─ Chunk 2
│  Diff 算法
│
├─ Chunk 3
│  最长递增子序列
│
└─ Chunk 4
   patchKeyedChildren
```

Query 只需要找：

```text
Chunk 3
```

而不是把整篇文章塞给 LLM。

我们会重点学：

- Fixed-size Chunk
- Recursive Chunk
- Semantic Chunk
- Heading Chunk
- Chunk Size
- Chunk Overlap
- Parent Document
- Metadata
- Chunk 太大有什么问题
- Chunk 太小有什么问题

而你的博客非常适合作为案例，因为你的数据结构已经明确存在：

```ts
KnowledgeChunk

id
articleId
articleTitle
url
anchor
heading
headingPath
category
tags
order
text
```

也就是说，你现在的博客实际上采用的是：

> **基于 Markdown Heading 层级的结构化 Chunk。**

以后面试官问：

> 你 RAG 的 Chunk 怎么做的？

你不能回答：

> 我不知道，好像框架自己切的。

你可以回答：

> 我的博客文章本身是 Markdown，非常具有结构语义，因此没有简单按 500 字暴力切块，而是利用 Heading 层级构造 Chunk，同时保留 headingPath、articleId、category、tags、URL Anchor 等 Metadata，既提高检索粒度，又方便最终返回真实来源。

这句话就开始有“项目深度”了。

> 为什么你的个人博客现在没有上向量数据库？

这就是工程判断。

# 第 8 章：AI Agent 到底是什么

这章是你未来方向的核心。

先打掉一个误区：

```text
ChatBot ≠ Agent
RAG ≠ Agent
LLM ≠ Agent
```

普通 Chat：

```text
User
 ↓
LLM
 ↓
Answer
```

Agent：

```text
User
 ↓
LLM
 ↓

 ↓

 ↓
观察结果
 ↓
继续决策
 ↓
调用 Tool
 ↓
最终完成目标
```

核心可以背成：

> Agent = LLM + Tools + Memory + Planning + Execution Loop。

例如：

```text

找出Vue内容不足的地方，
```

```text

```

Agent：

```text
读取博客
 ↓
统计文章
 ↓
判断主题
 ↓
搜索资料
 ↓
生成选题
 ↓
调用文件系统

```

这才叫 Agent。

# 第 10 章：MCP —— 必须彻底搞清楚

MCP：

> Model Context Protocol。

你可以先把它理解成：

> **AI 世界的 USB-C。**

以前：

```text
Claude → GitHub
Claude → MySQL
Claude → Filesystem
Codex → GitHub
Codex → MySQL
```

每个 AI 和每个工具都自己适配。

变成：

```text
             MCP
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   GitHub   MySQL   Filesystem
```

然后：

```text
Claude
Codex
其他 Agent
```

都可以通过统一协议发现和调用这些能力。

重点学：

```text
MCP Host
MCP Client
MCP Server
Tools
Resources
Prompts
Transport
stdio
HTTP
```

以及一定会问：

> MCP 和 Function Calling 有什么区别？

我们会专门背标准答案。

一句提前记住：

> Function Calling 解决“模型怎么调用函数”，MCP 更偏向“AI 应用如何用标准协议发现并连接外部工具和数据源”。

