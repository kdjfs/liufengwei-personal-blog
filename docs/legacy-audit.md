# 旧 Gemini 博客只读审计

审计对象：`D:\code\没用的项目\lfwBoKe（用Gemini生成的博客）`

审计日期：2026-08-01

本次只读取了项目结构与源码，没有修改、格式化、安装依赖或构建旧项目；`.env`、`.env.local` 的内容没有读取。旧项目中没有可迁移的本地图片、favicon、logo 或 Markdown 文件。

## 总体结论

旧项目是一个 Vite + Vue 3 + TypeScript 的单页原型，内容和页面状态集中在 `App.vue` 与 `constants.ts`。它更适合作为早期需求草稿，而不适合作为长期博客的工程基础。

主要问题不是“Vue 不好”，而是项目同时残留 Vue、React、CDN import map 与两套入口，路由、内容管理、SEO、静态生成和密钥边界都没有建立。继续在其上加功能会放大技术债，因此新项目只吸收产品意图，不迁移源码。

## 技术栈与结构

- Vue 3.4、Vite 5、TypeScript 5.2、Tailwind CSS 3（但实际通过 CDN 使用）。
- Google GenAI SDK 直接进入浏览器包。
- `App.vue` 手动维护 HOME / ARTICLE_DETAIL / ABOUT 三种视图，没有真实 URL 路由。
- `constants.ts` 硬编码四篇模拟文章，正文是模板字符串，不是 Markdown 内容文件。
- `components/` 下同时存在 `.vue` 和废弃 `.tsx` 占位文件。
- 根目录同时存在 `main.ts`、`index.tsx`、`App.vue`、`App.tsx`；`index.html` 又同时加载两个入口。

## 推荐迁移

推荐迁移的是产品层概念，不是源代码：

1. **文章卡片信息层级**：封面、日期、阅读时间、标题、摘要、标签的组合是合理的博客基础结构。
2. **顶部导航与极简页脚的意图**：可保留“清晰、低干扰”的方向，视觉重新设计。
3. **AI 摘要 / 博客助手的长期设想**：记录到 V8 Roadmap，当前版本不实现。
4. **关于页需要集中展示作者介绍**这一信息需求。

没有复制旧代码，也没有把旧站模拟文章、身份信息或外链图片迁入新站。

## 可以参考

- `BlogPost` 类型说明了旧站期望展示的基本文章字段，可用于反向确认新 Content Collection Schema 覆盖范围。
- 卡片 hover、sticky blur 导航、响应式三列列表等交互意图可以参考，但均需用新设计系统重写。
- AI 组件区分“当前文章上下文”和“全局问题”的产品想法，可以在未来 RAG 阶段重新评估。

## 建议重新实现

1. **页面路由**：用 Astro 文件路由生成真实的 `/blog/[slug]`、分类、标签和归档页面。
2. **文章系统**：从 JS 数组改为 Markdown / MDX + Astro Content Collections + Zod。
3. **样式系统**：旧站依赖 Tailwind CDN，生产构建与设计令牌不完整；新站使用本地 Tailwind 4 与 CSS Variables。
4. **导航与移动菜单**：旧移动按钮没有实际展开逻辑；需要键盘、ARIA 和当前页状态。
5. **Markdown 渲染**：旧站通过 `split('\n')` 手动切行，不支持真实语法树、代码高亮、TOC、表格或插件。
6. **SEO 与分享**：旧 SPA 没有文章级 canonical、OpenGraph、RSS 或 sitemap。
7. **搜索**：旧站没有全文索引；应使用构建期 Pagefind。
8. **主题与动效**：需要三态主题、无闪烁初始化和 `prefers-reduced-motion` 降级。

## 建议废弃

- `App.tsx`、`index.tsx` 以及所有仅写着 “Migrated to .vue” 的 TSX 文件。
- `ViewState` 驱动的伪路由和单组件页面切换。
- `constants.ts` 中硬编码的模拟文章、随机 Picsum 封面、虚构作者身份和经历。
- `index.html` 中 React/Vue/Vite 的 import map、Tailwind CDN 与双入口加载。
- `vite.config.ts` 把整个 `process.env` 注入浏览器的做法。它可能将本不该公开的变量一起打进前端代码。
- 浏览器直接调用 Gemini API 的实现。任何长期有效的服务端密钥都不应交给公开网页。
- 已经出现乱码的 README、注释、文案与文章内容。继续修补的成本高于重新建立 UTF-8 内容源。

## 明显 AI 生成痕迹与质量问题

- 大量“根组件 / 状态 / 方法”模板化注释重复代码本身，缺少对架构原因的解释。
- 模拟文章覆盖 React、AI、京都旅行、TypeScript 等互不相关主题，并虚构作者偏好与经历。
- UI 由常见的白底、靛蓝渐变、圆角卡片、浮动 AI 聊天气泡组合而成，缺少个人品牌辨识度。
- 包名、页面标题、作者名与文件注释互相不一致；一部分源码已产生严重乱码。
- 同一项目同时残留 Vue 与 React 生成结果，说明技术选择没有收敛。
